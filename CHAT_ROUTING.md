# Правило маршрутизации чатов: CubeGame ↔ Factoria

**Утверждено пользователем 2026-11-13.**

## 1. Первое слово выбирает проект

- Если пользователь начинает сообщение словом **«мод»** (например: `мод`, `мод,`, `мод:`), разговор относится **только** к **Factoria** — конвейеру моделей/ригов/анимаций.
- Если пользователь **не** использует такой префикс, разговор относится к основной игре **CubeGame**.
- Префикс задаёт проект для этой пользовательской задачи; при продолжении обсуждения уточняющие сообщения относятся к выбранной теме, если пользователь не переключил её явно.
- Когда указан **«мод»**, первым делом читать **этот репозиторий**, прежде всего рабочую ветку `factory/work`. **Не открывать и не читать репозиторий CubeGame** для такой задачи.
- Для обращений без «мод» работать по документам основного CubeGame; Factoria не изучать без отдельного запроса.
- Исключение только по прямому новому указанию пользователя обратиться к обоим проектам (например, задача миграции, интеграции или сравнения).

## 2. Порядок чтения Factoria

1. `AGENTS.md` (после публикации локального актуального файла DeepSeek).
2. `03_FACTORY_PROJECT_MEMORY.md` (после публикации локальной актуальной памяти).
3. `01_DEEPSEEK_FACTORY_IMPLEMENTATION_TZ.md` и `02_FACTORY_OPERATIONAL_DESIGN.md` (после синхронизации).
4. Последние отчёты, тесты и коммиты `factory/work`; только затем при надобности исторические материалы в `references/cubegame-m1/`.

На текущий момент часть названных файлов есть только локально и должна быть опубликована DeepSeek; **не утверждать, будто они уже на GitHub**.

## 3. Git/GitHub правила

- `main` = одобренная стабильная документация. Не менять без отдельного решения владельца.
- `factory/work` = текущая разработка, отчёты, опыты, код и межчатовая память.
- В работе держать один локальный проект `D:\Projects\CubeGame Factory`. Не переписывать локальную историю и не переносить старые копии из `CubeGameFactoryLab` без сравнения.
- После проверенной задачи: обновить память, сохранить доказательства в проекте, commit/push **обычный**; запрещён force-push.
- Не публиковать Alpha meshes, локальные .scratch assets, чужую геометрию, большие model weights, секреты или машинно-специфичные приватные данные.
- `READY_FOR_REVIEW` и `ACCEPTED` различаются: принятие за пользователем.

## 4. Цель

Работоспособный и повторяемый конвейер A (переработка существующих моделей) и B (генерация новых оригинальных), общий rigging/skinning/animation/export pipeline с уменьшением ручных правок на одну утверждённую модель. **Нет галочек без воспроизводимых доказательств.**
