# tools/alpha_research — извлечение статических таблиц Alpha 2013

Инструмент исследовательского контура M0-00B (issue #8). Читает **декомпилированный текст**
клиента `Cube.exe` (Alpha 2013) и восстанавливает статические словари, которые игра строит в
`cube::World::ctor_1 @ 0x0058eb00`.

Он **не** запускает игру, **не** обращается к `data*.db`, **не** публикует ассеты и не содержит
оригинального кода: на вход подаётся текстовое дерево декомпиляции, которое каждый исследователь
получает сам из своей копии игры (в CubeGame оно живёт только в `.scratch/`, `.gitignore`).

## Зачем

`M0-00B` описывает предметы, объекты города и способности по адресам и смещениям, но без имён и без
точного разделения «тип / подтип». Из этого конструктора извлекаются три таблицы:

| Таблица | Ключ | Что даёт |
|---|---|---|
| item | пара `(type, subtype)` | имена предметов: фляги, зелья, еда, оружие, дельтаплан, лодка, лампа, мана-куб |
| object | int | семантика объектов домов/города: двери, ловушки, сундук, прилавки, верстаки, мебель |
| skill | int | 11 рангов навыков и 16 узлов способностей (`AbilitySmash`, `AbilityCyclone`, …) |

## Использование

```powershell
python tools\alpha_research\extract_world_ctor_tables.py `
  <путь>\cube\world\World.cpp `
  <выход>\world_ctor_tables.json
```

Рядом с JSON пишутся `*.item.tsv`, `*.object.tsv`, `*.skill.tsv`.

## Правило восстановления значения

Вставка ведёт себя как `std::map::operator[]`: вызов возвращает слот значения, и присваивание
широкой строки, идущее **сразу после** вызова, заполняет этот слот.

Правило проверено тремя независимыми фактами (подробно —
[ALPHA_STATIC_TABLES_ITEM_SKILL.md](../../docs/research/alpha2013/ALPHA_STATIC_TABLES_ITEM_SKILL.md)):

1. `(2,0) = Formula` совпадает с независимо известным «рецепт = тип 2»;
2. `(8,0) = Amulet`, `(9,0) = Ring` совпадают с проверками типов в слотах `Equipment_sum_slot_values @ 0x446150`;
3. таблица навыков даёт 16/16 идентификаторов, совпадающих с ранее известным списком способностей.

## Ограничения (осознанные)

* Два блока декомпиляции (экипировка и «голова» списка оружия) печатают значение без переменной
  посредника. Альтернативное чтение там воспроизводит более старые опубликованные списки, но
  противоречит проверкам из п. 1–2. Скрипт выдаёт основное чтение и помечает такие строки
  `ambiguous`, а не «доказано».
* Строки вида `&DAT_xxxxxxx, n` — указатели в пул строк, а не литералы; они выгружаются как
  `resolved=false` и требуют отдельного чтения по адресу.
* Скрипт опирается на регулярные выражения по выводу Ghidra; при другой версии декомпилятора
  разметка (`local_3c`/`local_38`, порядок присваиваний) может отличаться — тогда нужен повторный
  аудит правила, а не «подгонка» чисел.

## Статус

`RESEARCH_DRAFT`. Не ТЗ, не разрешение на M0-01+, не приёмка S05B-2. Приёмку определяет продюсер.

# M1-R0 — реестр идентичности существ

`extract_creature_identity_registry.py` строит
[реестр существ](../../docs/research/M1_ALPHA_CREATURE_IDENTITY_REGISTRY.csv) для
[M1-R0](../../docs/planning/M1_CREATURE_FAMILY_RESEARCH_TASK.md): вид Alpha → имя → анатомия →
поведение → конкретный подготовленный Unity-вариант.

```powershell
python tools/alpha_research/extract_creature_identity_registry.py
python -m tools.alpha_content.build_staged_visuals --check   # дрейф реестра вариантов
```

Источники: таблица видов и слоты моделей `Cube.exe` (`ALPHA_CODE_STATIC`), карта имён из
`world/World.cpp` (`ALPHA_DECOMPILED`, wide-строки по `&DAT_` дочитываются из образа),
эмуляция `drawModel` и `CombatBehavior` (`EMULATED_ALPHA_CODE`), коммитированный реестр
`AlphaStagedVisuals.g.cs` (`UNITY_ASSET_VERIFIED`) и локальный кэш `.scratch/content` (`LOCAL_ONLY`).

Скрипт **только читает**: `Cube.exe`, `data1.db` (read-only sqlite), текст декомпиляции, локальный
кэш и сгенерированные C#-таблицы. В репозиторий пишется один текстовый CSV с именами, id, слотами
и статусами — без геометрии, без ассетов, без изменений Unity-проекта. Строки с неподтверждёнными
полями помечаются `INFERRED` / `UNKNOWN`, а не «доказано».
