## 1. Одна команда

```powershell
python scripts\orc02r\run_orc02r.py `
  --reference measurements\orc_reference.json `
  --profile scripts\orc02r\profiles\orc.json `
  --out outputs\prototypes\orc_02r\run1
```

Что делает команда (без ручных кликов):

1. читает существующий Orc **read-only** и снимает числа → `measurements/orc_reference.json`
   (если файла нет или указан `--remeasure`);
2. строит **новую** геометрию по числам профиля → `orc_new.glb` + `descriptor.json`;
3. повторяет генерацию во второй каталог → проверка детерминизма;
4. генерирует вариант с изменённым Orc Profile → проверка, что профиль реально влияет;
5. запускает Blender 5.2.4 headless → валидация, `.blend`, экспортный `.glb`, 3 вида;
6. пишет `report.json` и печатает статус.

Фактические измерения прогона: **91.08 с** всего, генератор **0.2 с**, Blender **90.0 с**,
пик RAM Blender **1277 МБ**, прирост VRAM **96 МБ** (рендер Cycles CPU), ручных действий — **0**.

## 2. Что взято от существующего Orc (только числа)

Источник: `CubeGame/.scratch/content/actors/d86_kind_0x0b_formula` (Alpha kind `0x0b`), read-only,
`rig.json` SHA-256 `d223eb3b…5363`. Ни одного вокселя/вершины источник в модель не передал.

| Параметр | Значение из источника | Как использовано |
|---|---|---|
| масштаб вокселя (`placementScale`) | 0.092857 м | база масштаба; новая сетка 0.03 м |
| рост (ствол + голова) | **1.848 м** | сверка: новая модель 1.92 м по макушке (**+3.9 %**) |
| торс (body) | 0.929 × 0.743 × 0.929 м | ориентир массивности |
| голова (с учётом clip-scale 0.9) | 1.504 × 1.170 × 0.919 м | ориентир крупной головы |
| кисть | 0.464 × 0.557 × 0.371 м | ориентир крупных кистей |
| стопа | 0.464 × 0.743 × 0.279 м | ориентир тяжёлых стоп |
| стойка (из клипа walk) | 0.557 м | проверка ширины стойки |
| палитра (наблюдённая) | зелёный, бронза, тёмный металл, фиолетово-коричневые волосы | идентичность цвета (см. ограничение L2) |

Полный JSON — [measurements/orc_reference.json](../../measurements/orc_reference.json). В нём же
зафиксировано, каких данных в источнике **нет**: отдельной геометрии плеча/предплечья и
бедра/голени, rest/bind pose, ширины плеч и таза по суставам. Эти величины получены
антропометрическим выводом от измеренного роста и записаны как `DERIVED_FROM_MEASURED`,
а не выданы за измерения.

## 3. Как построена новая геометрия

Архитектура: **HumanoidBase** (общий гуманоид) + **профиль** вида (данные, без правки кода).

```text
scripts/orc02r/
  voxelkit.py        Sculpt (единый объём), семантические уровни, greedy-merge, GLB-писатель
  humanoid_base.py   HumanoidBase: масса → мышцы → броня → лицо → волосы/борода → детали → резка стыков
  profiles/orc.json  Orc Profile: landmarks, widths, face, hair, beard, armor, palette
  measure_reference.py   снятие чисел с источника (единственный файл, знающий про CubeGame)
  generate_orc.py    NEW geometry: measurements + profile → GLB + descriptor
  run_orc02r.py      one-command оркестрация (reference → generate → determinism → variation → blender → report)
scripts/blender/orc02r_validate.py   headless-валидация + .blend + .glb + front/side/3-4
```

Ключевое отличие от ORC-02: модель строится **единым непрерывным объёмом**, а модульность
получается разметкой частей и удалением **одного слоя вокселей** на стыке. Поэтому
LEGO-сегментация не рвёт силуэт (претензия к ORC-02 устранена).

### Уровни детализации (смысловые, не случайный scatter)

| Уровень | Что делает | Воксели | Кубоиды |
|---|---|---|---|
| LARGE | силуэт: череп, грудная клетка, таз, трубы рук и ног, стопы, ладони | 6621 | 425 |
| MEDIUM | масса: дельтовидные, грудные, пресс, широчайшие, икры, ягодицы, броня, пояс, фартук, наручи, поножи, волосы, борода | 3730 | 336 |
| SMALL | лицо (глаза 2×1 с янтарной искрой, брови, усы, клыки, зубы), шрамы, боевая раскраска, швы ткани, кромки и заклёпки брони, костяшки, швы пальцев | 543 | 107 |
| **итого** | | **10 894** | **868** |

### Модули (20 независимых mesh-объектов, без скелета)

`head, eyes, brows, mouth, hair, beard, torso, pelvis, upper_arm_L/R, forearm_L/R, hand_L/R,
thigh_L/R, shin_L/R, foot_L/R`

Зазоры между сегментами (воксели по 0.03 м): плечо→предплечье **1**, предплечье→кисть **0** (наруч
закрывает шов), бедро→голень **1**, голень→стопа **1**, таз→торс **0** (пояс закрывает шов),
торс→голова **0** (шея). Это осознанное решение: «открытый» шов остаётся только на конечностях,
где он читается как LEGO-стык, а закрытые одеждой/шеей стыки не выглядят разрывами.

### Броня и одежда (новые, не из старой модели)

Асимметричный тяжёлый наплечник слева (тёмное железо + бронзовая кромка + заклёпки), кожаный
ремень на правом плече, X-упряжь на груди с бронзовой пряжкой, бронзовый торк на шее, широкий
пояс с пряжкой и заклёпками, набедренные ремни, тёмно-зелёный фартук с рваным низом, кожаные
наручи, наколенники, поножи, ботинки с железным носком.

## 7. Ограничения (честно)

| # | Ограничение | Следствие |
|---|---|---|
| L1 | Источник не содержит геометрии конечностей и rest-позы | длины плеча/предплечья/бедра/голени — выведены от роста (антропометрия), а не измерены; отмечено `DERIVED_FROM_MEASURED` |
| L2 | Наблюдённая палитра источника — яркая, «неоновая»; для «без мультяшности» взята приглушённая версия зелёного/бронзы/фиолета | цвет — авторское решение в профиле, не копия |
| L3 | Крупная «блоб-голова» источника (голова ≈ торс) несовместима с читаемым не-мультяшным силуэтом | голова уменьшена до 0.36 м (12 вокселей), рост сохранён (+3.9 %) |
| L4 | Сетка 0.03 м ограничивает лицо: глаз 2×1 воксель, клык 1 воксель, кисть без разделённых пальцев (швы цветом) | дальнейшая детализация лица — только меньшим вокселем или отдельным face-mesh, это следующее решение, не текущая задача |
| L5 | Плоские участки (грудь, бёдра) читаются как «плиты», наплечник выглядит коробкой | художественная правка профиля/форм — после решения владельца по направлению |
| L6 | Не проверено в Unity, нет рига/анимаций/эмоций | прямо запрещено условиями задачи |

## 8. Ручные действия

`MANUAL_STEPS = 0` в самом конвейере (все стадии headless). Вне конвейера: **6 итераций
профиля/форм** (силуэт, лицо, борода, броня, освещение рендера) — они зафиксированы
в истории профиля и не требуются для повторного прогона.
