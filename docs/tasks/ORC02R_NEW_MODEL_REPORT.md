## 1. Одна команда

```powershell
python scripts\orc02r\run_orc02r.py `
  --reference measurements\orc_reference.json `
  --profile scripts\orc02r\profiles\orc.json `
  --out outputs\prototypes\orc_02r\run1
```

1. читает существующий Orc **read-only** и снимает числа → `measurements/orc_reference.json`;
2. строит **новую** геометрию по числам профиля → `orc_new.glb` + `descriptor.json`;
3. повторяет генерацию → проверка детерминизма;
4. генерирует вариант с изменённым Orc Profile → проверка влияния профиля;
5. запускает Blender 5.2.4 headless → валидация, `.blend`, экспортный `.glb`, 3 вида;
6. пишет `report.json`.

Факт прогона: **91 s** всего, генератор **0.2 s**, Blender **72.5 s**, пик RAM Blender **1279 МБ**,
прирост VRAM **96 МБ** (Cycles CPU), ручных кликов — **0**.

## 2. Разделение источников

| Что | Откуда | Как использовано |
|---|---|---|
| Рост, масштаб | измерения старого Orc (read-only) | сохранён масштаб сетки 0.03 м и общая высота |
| Пропорции силуэта (крупная голова, короткие конечности, широкие плечи, тяжёлый торс) | **утверждённый визуальный эталон** | заданы в профиле как landmark-плоскости и ширины |
| Идентичность (зелёная кожа, клыки, уши, повязка, хохолок, тёмная одежда, красные акценты, один наплечник, булава, сумка) | **утверждённый визуальный эталон** | профиль + геометрия генератора |

Старый Orc больше не влияет ни на форму, ни на одежду — только на масштаб и контроль высоты.

## 3. Что построено

Архитектура: **HumanoidBase v3** (единый `Sculpt` → разметка частей → канавка на стыке)
+ **Orc Profile** (данные: landmarks, widths, face, hair, outfit, weapon, palette).

### Пропорции (воксели × 0.03 м)

| Плоскость | Значение | Доля роста |
|---|---|---|
| пол → макушка | 60 вокселей = **1.80 м** | 100 % |
| голова (подбородок→макушка) | 17 вокселей = 0.51 м | **28 %** |
| торс (пояс→плечо) | 13 вокселей = 0.39 м | 22 % |
| ноги (пол→пах) | 21 воксель = 0.63 м | 35 % |
| ширина плеч (по рукам) | 32 вокселя = 0.96 м | 53 % |

Против старого Orc: рост −2.6 % (1.80 против 1.848 м) — прежняя высота сохранена почти точно,
но силуэт перераспределён под эталон: голова выросла с 15 % до 28 % роста, ноги укоротились
с 50 % до 35 %, плечи расширились.

### Модули (21 независимый mesh, без скелета)

`head, eyes, brows, mouth, hair, torso, pelvis, upper_arm_L/R, forearm_L/R, hand_L/R,
thigh_L/R, shin_L/R, foot_L/R, pouch, weapon_club`

Борода удалена: на утверждённом эталоне её нет. `pouch` (сумка) и `weapon_club` (булава) —
отдельные слои-аксессуары, как требует задача.

| **итого** | | **16 676** | **889** |

### Стыки

Зазор сделан **канавкой**: на стыке снимается только наружная оболочка, внутренний сердечник
остаётся — модульность сохранена, но силуэт не разваливается (претензия к первой итерации).
Фактические зазоры по Z: плечо→предплечье **0**, бедро→голень **0**, голень→стопа **0**,
таз→торс **0**, торс→голова **0** (сегменты стыкуются, шов читается канавкой),
предплечье→кисть **1 воксель** (открытый LEGO-зазор). Пересечений модулей — **0**.
Стыки дополнительно прикрыты туникой, поясом и наплечником.

## 7. Ограничения

| # | Ограничение | Следствие |
|---|---|---|
| L1 | Сетка 0.03 м: глаз 3×1 воксель, клык 1 воксель, кисть без разделённых пальцев (швы цветом) | детализация лица ограничена разрешением |
| L2 | Наплечник читается как пластина с железной кромкой, а не как мягкая слоистая кожа | можно улучшить формой слоёв |
| L3 | Пропорции эталона (голова 28 %) — компромисс: эталон около 39 %, но при 39 % лицо теряет пиксельную читаемость | дальнейшее увеличение головы — отдельное решение |
| L4 | Булава пересекает кулак (так она «держится»); это осознанно и исключено из проверки стыков | аксессуар, не часть тела |
| L5 | Нет рига/анимаций/эмоций и проверки в Unity | запрещено условиями задачи |

## 8. Ручные действия

`MANUAL_STEPS = 0` в конвейере. Вне конвейера — итерации профиля/форм по рендерам
(силуэт, лицо, одежда, стыки); для повторного прогона не требуются.
