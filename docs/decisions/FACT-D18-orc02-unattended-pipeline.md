# FACT-D18 — ORC-02: конвейер автономной переработки существующего Orc

**Решение владельца:** 2026-11-13. **Статус:** APPROVED DIRECTION / NOT IMPLEMENTED.  
**Репозиторий:** `alfuwerce-art/factoria`, рабочая ветка `factory/work`.  
**Связано:** [FACT-D17](FACT-D17-character-visual-first-face-emotions.md), [ORC-01](../prototypes/ORC01_LOCAL_VALIDATION.md).

## Главная цель

**КОРРЕКЦИЯ ВЛАДЕЛЬЦА 2026-11-13:** существующий Orc CubeGame используется **только как источник пропорций, силуэта и анатомических ориентиров**. Запрещено считать задачей разрезание его старой геометрии на модули, масштабирование этих модулей или повторную сборку старых вокселей.

Цель ORC-02R — построить запускной, повторяемый конвейер, который по измерениям/референсу старого Orc **процедурно создаёт НОВУЮ 3D-геометрию с нуля**: новый торс, новую голову, новые руки/ноги, одежду/броню, лицо и кубическую детализацию разных размеров. Старые вершины/воксели не должны становиться геометрией финального результата.

Успех — `existing Orc reference → measurements/proportions → procedural humanoid/orc profile → NEW voxel geometry → preview + editable .blend + .glb + report`, воспроизводимый **одной командой** и без ручных кликов в Blender. После появления новой модели она уже организуется в логические LEGO-модули для будущего рига.

## Источник

- Использовать **существующий Orc CubeGame только как read-only reference** для измерений: рост, ширина плеч/торса, размер головы, длины конечностей, общая расовая форма. **Не переносить его воксели/вершины в финальную модель и не пересобирать исходную геометрию.** Финальный mesh должен быть создан процедурно заново.
- Разрешён только read-only поиск и создание отдельной **локальной рабочей копии** для Factoria без изменения CubeGame, Unity-сцен, Prefab, игрового кода, git refs, Alpha-файлов и `.scratch/content`. Не копировать исходный закрытый контент и производные меши в публичный GitHub. Перед использованием выяснить происхождение/лицензию. Исходную Alpha-геометрию не объявлять автоматически коммерчески пригодной: финальная оригинальная геометрия требует самостоятельного дизайна и правовой оценки.
- Если чистый рабочий mesh недоступен из разрешённого пути, закончить этап `BLOCKED_SOURCE` с конкретной причиной, не подменять вход искусственным орком.

## Требования к конвейеру

1. **Headless/CLI + config:** одна команда в изолированном каталоге Factoria; manifest входа и JSON-конфиг (family=humanoid, profile=orc, seed, детализация, output paths). Без ручных действий в Blender между стадиями.
2. **Неразрушаемость:** исходный файл read-only; отдельные versioned outputs; отказ от перезаписи принятых ассетов; checkpoint/restart после сбоя.
3. **Контракт сегментов:** голова (челюсть встроена), глаза, брови, рот; волосы и борода как опциональные независимые модули; торс/таз, плечо, предплечье, кисть, бедро, голень, стопа слева/справа. Геометрия с разрывами и незавершёнными кубическими стыками. Пока **без** скелета, skinning, анимаций и эмоций; части должны оставаться пригодными для их будущего присоединения.
4. **Детализация:** кубы **разных размеров**, иерархия крупная форма/средняя/мелкая деталь, без гладкой мультяшной формы или бессмысленного случайного шума. Лицо пиксельное и более выразительное, умеренно детализированное. Не выдавать простое размножение боксов за художественную переработку.
5. **Машинная проверка:** число модулей, неразрушаемые входы, оси, масштаб, пересечения и зазоры, целостность сетки, GLB round-trip, сохранение/открытие .blend, reproducibility, wall time, RAM/VRAM; ошибки валидатора блокируют PASS.
6. **Автономный результат:** .blend/.glb, фронт/профиль/3-4, manifest, JSON-отчёт с явными ручными операциями и блокерами. При техническом дефекте workflow должен остановиться и написать понятную ошибку, а не тихо сделать неверную модель.
7. **Масштабирование позже:** правила профиля Orc не должны быть жёстко прошиты внутрь общего конвейера; семейства/варианты задаются данными. Сначала 1 модель, затем по отдельному разрешению 2→5→10→25→50.
8. **Приёмка:** сначала доказать, что автоматизация технически работает на **реальном источнике Orc**, затем показать владельцу художественный результат. `PIPELINE_TECH_PASS` ≠ `MODEL_APPROVED`. После `MODEL_APPROVED` отдельно экспериментировать с эмоциями (FACT-D17).
9. **Ресурсы:** режим CPU-first, для AI (если понадобится и будет отдельно разрешён): максимум 15 ГБ RAM / +2 ГБ VRAM на всю задачу. Не загружать тяжёлые модели без согласования. Не объявлять ограничение VRAM гарантированным без измерений.

## Граница разрешения

Владелец разрешил начать **один изолированный ORC-02 эксперимент с кодом конвейера и реальным исходником**, в объёме настоящего решения. Это исключение из старого запрета на художественный прототип во время PREP; оно **не** открывает M1, не разрешает изменение Unity, массовую обработку, создание AI-весов, рига, анимаций или интеграции в игру. PREP-02 остаётся самостоятельным незавершённым этапом.

## Готовность этапа

- `PIPELINE_TECH_PASS`: два последовательных headless-прогона исходного Orc с одинаковым seed, валидными артефактами, без обязательных ручных кликов, плюс журналы фактического расхода ресурсов.
- `MODEL_PENDING_REVIEW`: технический результат есть, но художественный эталон не утверждён.
- `MODEL_REWORK` / `MODEL_APPROVED`: только явным решением владельца.
- Если исходник/алгоритм/детализация не готовы — `PARTIAL` или `BLOCKED` с фактической причиной, а не зелёная галочка.
